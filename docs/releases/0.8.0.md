# HA Growatt 0.8.0

The Home Assistant-only receiver has now received live traffic from the
owner's MIN 2500TL-XH and MIC 2000TL-X. Both feeds kept updating through a
controlled Growatt cloud outage, and cloud forwarding reconnected afterwards.
The temporary transparent relay left the loggers' production settings alone;
it did not test a permanent logger-to-Home-Assistant installation. The
[hardware record](../native-hardware-test-2026-09-24.md) gives the observations
and limits.

For owners with a separately accessible Modbus connection, the integration
adds read-only serial RTU and UDP options alongside TCP. UDP supports socket
(MBAP) and RTU datagram framing. The MIN/MIC auto-selector now uses device type
codes conservatively; a three-string or three-phase profile needs a deliberate
choice and a matching register table. Optional faster polls update current
power without refreshing energy totals or their timestamps. These connections
and expanded profiles passed test-gateway checks, not physical Modbus tests on
the owner's ShineWiFi-X hardware.

An optional diagnostic sensor counts unfamiliar Shine packet shapes. It is
off by default and contains no packet bytes, serial numbers, readings or exact
times. Fixed-offset Shine uploads do not declare a safe range for unnamed
numeric values, so this release does not publish raw unknown-value sensors.

The existing app and MQTT route remains in use on the owner's production Home
Assistant. No entities, history or Energy Dashboard sources are moved by this
release. Local checks passed 3,143 tests on Python 3.12, 3.13 and 3.14,
disposable Home Assistant Core setup and restart probes, and installed service
probes on amd64, arm64, ARMv7 and 386. The direct Modbus hardware gap remains
open until an owner with a suitable gateway checks live readings.
