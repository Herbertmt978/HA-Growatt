# HA Growatt 0.9.0

The shareable Shine capture report now shows bounded two-byte positions that
changed between unfamiliar measurement packets. When at least two samples
decode completely and plausibly with a built-in layout, it suggests up to
three profile names for private review. The report contains positions and
names, not packet bytes, serials, timestamps or readings. It does not create
sensors or a loadable profile. A candidate is a lead: varied real readings,
manufacturer information and a synthetic replay fixture are still needed
before a new model can be supported confidently. The existing serial-redacted
replay remains a separate private download.

The Home Assistant direct-Modbus options now keep an entry attached to its
original connection and unit. Changing the transport, address, framing or
unit requires a new entry, which keeps another inverter's readings out of
the old entity history. Profile and polling adjustments remain possible on
the original entry. No serial is claimed from an unreliable or unavailable
register. Replacing hardware behind an unchanged gateway and unit cannot be
detected automatically and also needs a new entry. This release makes no new
claim of physical Modbus compatibility for the owner's ShineWiFi-X installation.

The app and MQTT route remains installed on the owner's production Home
Assistant. This release does not redirect the dataloggers or migrate its
entities. The 3,155 Python tests passed on 3.12, 3.13, 3.14 and Linux 3.13.
Disposable Home Assistant Core 2026.9.3 checks covered native Shine setup,
the Modbus options flow, entity identity and a quiet restart. Installed
service checks passed on amd64, arm64, ARMv7 and 386, and the app's Supervisor
path passed on both supported architectures. No unfamiliar physical Shine
model or direct Modbus gateway was available to qualify the new workflow.
See the [feature guide](../home-assistant-features.md) for the capture workflow
and Modbus entry change instructions.
