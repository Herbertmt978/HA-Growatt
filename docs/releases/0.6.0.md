# HA Growatt 0.6.0

You can now run HA Growatt as one Home Assistant integration. It listens for
Growatt dataloggers itself and creates native sensors, so new installations do
not need the separate app or MQTT broker for readings. Cloud forwarding and
automatic local fallback are available in this route. Saved readings return
after a quiet restart, while the Connected sensor waits for a live packet.

The existing app and MQTT route is unchanged. It remains the choice for the
web support page, other output destinations and supported inverter controls.
Native sensors use new identifiers; adding this route does not rename or take
over existing MQTT entities. Preview any history adoption and check Energy
Dashboard sources before moving a datalogger to the new receiver.

The short-lived private packet capture now offers a shareable structure report
for packets that cannot be decoded. It groups unfamiliar packet shapes and
shows which 32-byte blocks are active or change between samples. It includes
safe decode categories and compatible built-in headers, but no packet bytes,
serial numbers, exact times or measurement values. A matching header alone is
not proof that a profile decodes the packet. The app offers the download in
its support page; the native integration offers the `capture_evidence` action.

The native route has passed synthetic packet, TCP receiver, restart, decoding
and Home Assistant validation checks. Physical datalogger testing is limited
to the owner's existing two-inverter app installation until the route is tried
on hardware. No additional inverter write control is claimed for the native
route. See the [Home Assistant guide](../home-assistant-features.md) for setup
and the limits of each installation route.
