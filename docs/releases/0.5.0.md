HA Growatt 0.5.0 adds separate datalogger devices, clearer inverter and packet diagnostics, read-only hardware identification, and register inspection in the app and optional companion. Existing measurement identifiers and Recorder history are preserved. Update both components to use the companion's new actions.

The companion checks for a fresh app status on Home Assistant's MQTT broker during setup. An old retained status cannot make a disconnected app look live; setup remains available if the app is offline. The app's guide now links directly to the companion installation and explains which component receives datalogger traffic.

For unfamiliar hardware, a separate command-line tool can scan bounded input and holding register ranges on an explicitly named **direct Modbus TCP** gateway. It sends only reads, paces requests and saves raw values as a private report. The [hardware matrix](https://github.com/Herbertmt978/HA-Growatt/blob/v0.5.0/docs/hardware-matrix.md) includes published 0xAHA results, clearly marked as external direct-Modbus evidence. Those results do not verify HA Growatt's Shine connection or battery controls.

The owner's MIN 2500TL-XH and MIC 2000TL-X with ShineWiFi-X dataloggers remain the physically verified telemetry installation. No separate direct-Modbus endpoint or battery write has been qualified on that hardware. Experimental controls remain off by default.

Local validation passed on Python 3.12, 3.13 and 3.14, including 3,059 tests, lint, packaging and isolated Home Assistant/MQTT feature and cold-restart checks. Installed-container probes passed on amd64, arm64, arm/v7 and 386. The live installation should be checked again after updating the app and companion, particularly for fresh readings from both inverters, cloud forwarding, MQTT discovery, setup guidance and retained history.
