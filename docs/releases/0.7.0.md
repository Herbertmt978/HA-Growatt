# HA Growatt 0.7.0

The Home Assistant-only Shine receiver now offers supported inverter settings,
optional output destinations and more useful support information. Controls are
off by default. A setting becomes available only after the current datalogger
connection answers a read, and a change is read back before Home Assistant
shows it as applied. Battery settings and schedules need a second experimental
switch and an owner-entered physical model that matches the selected profile.
Local-server setting requests follow the datalogger's one-second command pace.

Raw MQTT, PVOutput, InfluxDB and HTTP outputs can be configured separately.
They use bounded queues, so a slow destination cannot hold up datalogger
traffic. A saved password or token is not carried to a changed destination.
Home Assistant exposes connection and packet counters and downloadable
redacted integration and device diagnostics. The app still provides its guided
web page, CSV output and Python extensions.

This release also adds continuous read-only Modbus TCP polling for a separately
accessible inverter or gateway. Choose a documented MIN, MIC or legacy input
register profile and a stable device identity. A failed read leaves the last
good measurements in place and marks the connection offline. The Connected
sensor appears even before the first successful reading. Saved readings
return after a quiet restart without pretending that the gateway is live. This
route does not use the Shine upload connection, forward to Growatt or write
registers.
Modbus failure notices follow the configured daylight-alert and startup grace
settings.

The two ShineWiFi-X feeds in the owner's installation have been checked through
the existing app route, not through the new Modbus TCP route or the Home
Assistant-only receiver. No direct Modbus endpoint has been confirmed there.
Battery controls and schedules have synthetic protocol tests but no compatible
physical battery inverter test. Keep those features disabled until they can be
qualified on the intended model. The existing app and MQTT entities, statistics
and Energy configuration do not move when the new routes are installed.

Local checks covered 3,097 tests on Python 3.12, 3.13 and 3.14 and the installed
Linux package, all four supported container platforms, Hassfest and package
builds. Disposable Home Assistant instances exercised both connection routes,
including a quiet restart. The Home Assistant development instance passed its
configuration check and Core restart. The connection checks used synthetic
datalogger and Modbus replies; they did not send commands to physical hardware.
